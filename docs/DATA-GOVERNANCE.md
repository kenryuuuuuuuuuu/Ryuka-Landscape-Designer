# Data Governance — 固定値と設計データの管理

最終更新: 2026-08-07

本書はデータの内容ではなく、どのデータを正本とし、どの条件で変更できるかを定める。現在の形状と代表値は[`MODEL-SPEC.md`](MODEL-SPEC.md)、コード構成は[`ARCHITECTURE.md`](ARCHITECTURE.md)を参照する。

## 保護対象

敷地外周、辺長、建物中心・寸法・開口部、敷地・宅地面積、緯度・経度、園路、輪作区画、果樹・植物・施設の初期座標を固定データとして扱う。機械可読な正本は`data/fixed-site-data.js`である。

固定値に対するPLAN A/Bの移動・追加・削除結果は設計差分であり、固定データではない。`plantLayout`、`objectLayout`、`groundLayout`として保存し、`window.DATA`へ書き戻さない。

## 変更ルール

1. 表示品質、素材、季節、成長年数、PLAN、REAL / PLANの変更を理由に固定データを書き換えない。
2. 固定データを変更する場合は、測量成果、設計図、現地確認、利用者判断などの根拠をPRへ記録する。
3. 変更前後の座標・寸法を機械比較し、意図した差分だけであることを確認する。
4. `data/fixed-site-data.js`の再帰的な`Object.freeze`を維持する。
5. `MODEL-SPEC.md`に掲載した代表値または意味が変わる場合は、同じPRで文書を更新する。
6. 一時的な表示調整値は固定データへ追加せず、該当modelまたはmaterialモジュールで管理する。

新しい実装や仕様変更は、コードと関連文書を同じブランチ・同じPull Requestで更新して完了とする。詳細な更新先はリポジトリ直下の`AGENTS.md`と`docs/README.md`に従う。文書変更が不要な場合は、Pull Request本文に理由を明記する。

## 起動時検証

起動時に敷地点数、建物寸法、敷地面積、宅地面積、必須データ、凍結状態を検証する。異常は`console.error`と画面上の警告で通知し、固定データが不正な場合は3D初期化を続行しない。

変更時は少なくとも次を確認する。

- JavaScript構文チェック
- 固定データ検証
- 座標・寸法差分
- `git diff --check`
- REAL / PLANおよび対象ワークスペースでの表示
- 必要に応じてPC幅と390px前後のスマホ幅
