# Green Manure Spec — 緑肥・グランドカバー層の追加

- バージョン: v1.0
- 更新者: Claude（拳竜さんの依頼により作成）
- 日付: 2026-08-01
- 対象ブランチ: `feature/green-manure`（mainから分岐）
- 前提: Phase 1〜2c（ワークスペース統合）が完了していること

## 0. これは何か

畑650㎡のうち、まだ用途が決まっていない**空白339.3㎡**に、緑肥（りょくひ）とグランドカバーを割り当てる。目的は「使わない土地を、最小の手間で、見られる状態に保つ」こと。放置すると日田の夏は1か月で1m級の雑草に覆われるため、空白のまま残す選択肢は存在しない。

**重要な設計判断**：新しいレイヤー（`groups.greenManure`等）は作らない。既存の `ground-feature` システムに緑肥タイプを追加する形で実装する。理由は3章。

## 1. スコープ

**含まれるもの**

1. `ground-feature-catalog.js` への緑肥3タイプの追加（材質＋カタログ項目）
2. `ground-feature-models.js` のマテリアル対応表への追加
3. `createBaseGroundFeatures()` への11区画（G1〜G7）の追加
4. LANDSCAPE LAYERS の凡例に緑肥カテゴリを追加

**含まれないもの**

- 既存の畑オブジェクト（輪作・果樹・ハーブ帯・園路）の座標変更
- 季節変化・成長年数に応じた緑肥の見た目変化（将来の拡張候補）
- 播種・刈取りのスケジュール管理機能（別途 Markdown で管理する）

## 2. 背景：なぜ空白が339.3㎡なのか

デジタルツインの実データから幾何学的に算出した。

| 区分 | 面積 |
|---|---|
| 敷地全体 | 971.0㎡ |
| うち宅地 | 319.7㎡ |
| **畑エリア** | **650.1㎡** |
| うち既存の作付け・園路・施設 | 310.8㎡ |
| **空白（今回の対象）** | **339.3㎡（畑の52%）** |

**果樹の株元は空白に含めている。** 果樹の下を草地に保つ「草生栽培」は果樹園の定石であり、土壌流亡防止と管理省力化の両方に効く。除外すべきものではない。

## 3. なぜ新レイヤーを作らないか

リポジトリには既に `ground-feature` システム（`ground-feature-catalog.js` / `-editor.js` / `-models.js`）があり、以下を備えている。

- `area-clover`（クローバー）を含む材質定義
- ドラッグによる編集、頂点追加・削除
- PLAN A/B の差分管理、undo/redo
- 面積の自動集計（`updateGroundTotals()` で「芝・クローバー」として合算表示）

緑肥を独立レイヤーで実装すると、これら全てを再実装することになる。**既存カタログに項目を足すだけで、編集可能・PLAN比較可能・面積集計対応が無料で手に入る。** `FIXED-DATA-POLICY.md` の思想（固定データと実行時状態の分離）とも整合する。

## 4. 材質とカタログの追加

### 4.1 `js/ground-feature-catalog.js` の `MATERIALS` に追加

```js
'area-crimson-clover': Object.freeze({ label: 'クリムソンクローバー', kind: 'area' }),
'area-green-manure':   Object.freeze({ label: '緑肥（ソルゴー/ベッチ）', kind: 'area' }),
```

### 4.2 同ファイルの `CATALOG` に追加

```js
feature({ featureType: 'crimson-clover', label: 'クリムソンクローバー', kind: 'area',
  category: 'green', defaultLayer: 'lawn', materialId: 'area-crimson-clover',
  defaultWidth: 0, description: '春に赤い花が咲く緑肥。秋播き、翌5月に刈る' }),
feature({ featureType: 'green-manure', label: '緑肥ローテーション', kind: 'area',
  category: 'green', defaultLayer: 'lawn', materialId: 'area-green-manure',
  defaultWidth: 0, description: '夏ソルゴー→秋ヘアリーベッチ。将来の菜園予定地' }),
```

`clover`（既存）はそのまま使う。新規追加は2タイプのみ。

### 4.3 マテリアルの割り当て（`js/ground-feature-models.js`）

材質IDから実際のThree.jsマテリアルへの対応は `ground-materials.js` ではなく、`js/ground-feature-models.js` の `plan` / `real` の2つの対応表（253〜268行目付近）で解決されている。ここに2件ずつ追加する。

```js
// plan（設計図表示）に追加
'area-crimson-clover': new THREE.MeshBasicMaterial({ color: 0xc07078 }),
'area-green-manure':   new THREE.MeshBasicMaterial({ color: 0x7d8f5a }),

// real（実景表示）に追加
'area-crimson-clover': ground.clover,   // 暫定。専用テクスチャは後述
'area-green-manure':   ground.clover,   // 暫定
```

**REAL表示の質感について**：まずは既存の `ground.clover` を暫定で流用し、動作を確認する。専用テクスチャを作る場合は `js/ground-materials.js` に `crimsonClover` / `greenManure` を追加し、`area-clover` の実装（`ground.clover`）を参考に同じ生成パターンで作る。

| 材質 | 基調色 | 質感の方向 |
|---|---|---|
| `area-crimson-clover` | `#c07078` | 赤紫の花が点在する低草。クローバーより粗いノイズ |
| `area-green-manure` | `#7d8f5a` | 草丈のある緑肥。縦方向のストライプを弱く入れる |

**注意**：色を鮮やかにしすぎると3D全体で浮く。既存の `area-lawn` / `area-clover` と並べて確認し、彩度を揃えること。専用テクスチャの作成は必須ではなく、暫定流用のままPRを出してもよい（その場合はPRにその旨を明記する）。

### 5.2 G7「こぼれ地」について

果樹の間や通路際の細かい隙間の集合で、4区画・合計126.6㎡と**2番目に大きい**。1箇所ずつは小さいため見落とされやすいが、放置すると雑草の発生源になって畑全体に広がる。独立したゾーンとして明示的に管理する。

## 6. UI の追加

### 6.1 LANDSCAPE LAYERS の凡例

`js/app.js` の `layerDefs` は既存の7項目（施設・園路・収穫ガーデン・ハーブ帯・輪作区画・果樹・広場）。緑肥は `layer: 'lawn'` に属するため、**既存の「広場・パーゴラ」トグルで一緒に表示/非表示される**。

緑肥だけを独立してトグルしたい場合は、`layerDefs` に項目を追加するのではなく、GROUND EDIT 側のカテゴリフィルタで対応する方が構造的に正しい。まずは既存の挙動のままとし、実際に使ってみて不便なら次のPRで検討する。

### 6.2 面積集計

`updateGroundTotals()` の `green` の計算式に、新しい2材質を加算する。

```js
const green = (areas['area-lawn']||0) + (areas['area-clover']||0)
            + (areas['area-crimson-clover']||0) + (areas['area-green-manure']||0);
```

表示ラベルを「芝・クローバー」から「**芝・クローバー・緑肥**」に変更する。

## 8. 作業手順（Codexへの指示テンプレート）

```
1. ブランチ feature/green-manure を作成
2. docs/GREEN-MANURE-SPEC.md の4〜6章に従って実装
3. node --check を全JSファイルに実行
4. 既存テスト（scripts/ 配下）を全て実行
5. ブラウザ(1440x900)で index.html を開き、以下を確認:
   - 起動時警告が出ないこと
   - 畑ワークスペースで、空白だった部分が緑・赤の地表で埋まっていること
   - G1（西端）が赤系、G2（南）が緑肥色、他が白クローバー色で描き分けられること
   - 緑肥の色が既存の芝・クローバーと並べて違和感のない彩度であること
   - GROUND EDIT で緑肥区画をクリックして選択・編集できること
   - PLAN A/B を切り替えても破綻しないこと
   - 地表集計に「芝・クローバー・緑肥」として面積が加算されていること
6. 確認できたらコミット
   （メッセージ: 緑肥・グランドカバー層を追加、空白339㎡を全域割り当て）
7. PRを作成しDraft状態にする
```

## 9. 留保事項

- **区画の形は暫定である**。デジタルツイン上の空白を幾何学的に埋めたもので、現地の日照・水はけ・傾斜は考慮していない。土壌診断と現地確認の後、GROUND EDIT で調整することを前提とする
- **植物の選定は造園の専門家によるものではない**。クリムソンクローバー・ソルゴー・ヘアリーベッチはいずれも温暖地で一般的な緑肥だが、日田での播種適期・入手先・地域特有の事情（獣害等）は真悟さんへの確認が必要
- **獣害対策が未反映**。イノシシ・シカが出る地域の場合、柵の位置がレイアウト全体の前提を変える。柵が決まった時点で本仕様の見直しが必要になる可能性がある
- **G2は将来の菜園予定地**。2〜3年目に輪作E・Fへ転換する想定なので、そのとき本区画は削除または縮小される
